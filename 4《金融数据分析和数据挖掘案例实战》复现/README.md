在本目录的PowerShell运行全部案例：

```powershell
.venv\Scripts\python.exe 运行全部.py
```

仅运行一个案例，可加文件名关键词，例如：

```powershell
.venv\Scripts\python.exe 运行全部.py "Vintage"
```

## 与原代码的必要差异

- 数据来自教材文件；教材固定节点/边作为明确标注的教学示例保留，不称为真实客户。跳过随机造图与SMOTE系列合成记录。随机过抽样只重复已有训练行，代码核对了来源。
- 营销原始流水重建与教材宽表的部分收入/支出汇总不一致，提供差异核对及相同测试客户上的模型对照，不猜测差异原因。
- 评分卡使用训练集拟合分箱、WOE与筛选；以二分类伯努利似然计算Logit AIC，修正原默认OLS口径。评分时输入原始特征，避免对WOE再次错误分箱；逐项分数与概率换算已设置断言核对。
- B卡修复循环重复拼接、后缀叠加和消费CV误用余额CV；按客户分区。数据未标明目标观察期，不能保证其是严格的前瞻验证。
- 反欺诈从原始关系表重建全量网络，不依赖附带的16行残缺中间表。只使用截至申请日的边和此前已知的他人风险事件。按日批处理不能还原日内先后，随机分区测试也不替代未来时间外验证。
- 反欺诈基础表有3个重复且信息冲突的客户号，排除其全部6条记录后按唯一客户分区，冲突原记录保留供核对，不任意更改标签。
- 贝叶斯调参使用教材参数范围，5次初始探索加15次迭代、5折验证，少于教材50次迭代；结果是本次搜索结果，不声称全局最优。
- LightGBM叶子数按树深限制，最小Hessian取至少0.001；无效候选明确标记，不伪造验证AUC。
- Vintage直接解析SQL中的INSERT，不连接服务器、不执行SQL。未观测账龄保持缺失，分母为原始放款金额。
- 原社群算法未匹配 `Weight` 或中文边权字段，因此保留未加权基准，额外给出明确加权对照。PageRank原矩阵第4列和为5/6，先按列归一化再迭代。
- 第9章使用本资料第2章的实际交易日，修复三个滞后列全为shift(1)的问题；不补造时分秒或无交易日期。
